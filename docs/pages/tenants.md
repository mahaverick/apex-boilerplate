# Tenants

The tenant list (`/tenants/`), a tenant's tabs under `/tenants/$tenantId`, and the tenant actions menu. Back to the [route map](README.md#route-map).

## Layout

`/tenants/$tenantId` (`src/pages/_app/tenants/$tenantId.tsx`) is the layout every tenant tab renders in, under `AppLayout` ([overview.md](overview.md#the-staff-shell)).

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fetches         | Its loader starts `GET /platform/tenants/:id` (`['platform', 'tenant', id]`; a 404 is not retried) without awaiting it, so the router never holds the page: the layout draws at once. On a first visit, when the route's code takes more than 300 ms to arrive, `DetailPending` shows until it does; there is no boot wait beyond `_app`'s flags read. Every tab reads the same cached detail.                                                                                                                                                                                                                                        |
| While it loads  | A visually hidden `h1` "Tenant" over the header's shape: a name bar (`h-8 w-64`) and a line bar (`h-5 w-48`) beside an actions bar (`h-9 w-28`), then the real tab bar and the `Outlet`. Overview, Flags, Onboarding and Emails draw their own skeletons; Members, Invitations and Activity stay blank until the detail is in. The loaded header replaces only the skeleton part. The breadcrumb reads Tenants › Tenant › {tab} until the detail is in. The skeleton's sizes follow the loaded header's text sizes; they were not measured against it. While the tenant loads the layout's root is `aria-busy`.                       |
| Gate panels     | A 404 renders an `EmptyState` with the `h1` **Tenant not found**, "It doesn’t exist, or your role changed. If your role changed, reload the page." and Back to tenants. Any other failure renders one `LoadError`, "We couldn’t load this tenant. Select Try again.", whose Try again refetches the detail; it replaces the header, the tabs and the tab, and offers no way back but the breadcrumb. A failed refetch while the tenant is on screen keeps the header, the tabs and the tab, with the same `LoadError` above them; only a 404 still replaces the page.                                                                 |
| Header and tabs | The tenant's name as the `h1` with its state badge (`TenantStateBadge`), then "`{slug}` · Created {date}", and the **Actions** menu on the right. Below, a `nav` "Tenant sections" of link tabs (bottom-bordered `Link`s, hand-rolled): Overview, Members, Invitations, Activity, Emails, Onboarding, Billing, Flags. Flags has `minRole: 'admin'` in `TENANT_DETAIL_TABS` (`src/constants/tenant-tabs.ts`) and is left out of the nav below admin. Billing has `customerOnly`, so the platform tenant (the staff team), which has no billing, leaves it out. On a phone the bar scrolls sideways with no sign that more tabs follow. |
| Actions menu    | `TenantActionsMenu` (`src/components/features/tenants/tenant-actions-menu.tsx`), shown only when one action applies: Edit details, Resend owner invitation (no active owner), Suspend, Reactivate, Archive (admins and up, by lifecycle state) and Delete permanently (owners, archived tenants). Each opens a dialog; the destructive ones go through `ReasonDialog` and the shared step-up dialog. A viewer gets no menu at all.                                                                                                                                                                                                    |
| Breadcrumbs     | Tenants › {name} › {tab}. The name comes from the same detail query (`TenantCrumb`), so it reads "Tenant" while the detail loads.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

In the walk, a load of `/tenants/{id}/members` with the detail held for 2.5 s showed the shell, the breadcrumb Tenants › Tenant › Members and the header skeleton for the whole 2.5 s; the members request started only after the detail answered. With only `GET /tenants/:slug/members` failing, the header and tabs stayed and the Members card showed its own `LoadError`. The capture's error shots fail the detail, so every tab's error shot is the layout's `LoadError` alone.

![Members](img/tenants/tenant-members--default.jpg)

|                     |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Purpose             | Who has access to the tenant, with role changes and removal; staff acting through platform access give a reason.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| File                | `src/pages/_app/tenants/$tenantId.members.tsx`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Guard and redirects | `_app`, then the [layout](#layout). A suspended or archived tenant renders `FrozenTenant` ("This tenant is {state}. | Sections            | One **Members** card (`MembersCard`): "Everyone with access to this tenant.", then a `DataTable` of Name, Email, Role (a `Select` where the caller may change it) and Actions (Remove or Leave), with a search box, a Role facet, sortable Name, Email and Role headers and cursor paging; below `md` the rows become bordered cards. Its dates follow react's billing page: "Trial ends" only while the tenant is trialing (express keeps the trial date afterwards), "First charge {price} on {date}" for a tenant that took Paid during its trial and has not been charged, "Cancels on" in place of "Paid until" while the subscription ends at its period end, and "Period ended" with "Moves to Free on" (three days later, express's buffer) once a cancelled period has ended. Free shows no dates, since express keeps the last period's end after the move. It also shows "Payment failed on {date}. Paid ends on {date}." or "… The payment provider is still retrying." for a failed payment, "Dispute open" as a destructive badge, and copy buttons for each subscription id. With payments off, a note says nothing can be charged or synced, the subscription ids are left out, and the Invoices card says they can't be read and asks nothing. The billing email is owner-only, so staff never see it. Payer names, grant authors and grant reasons are masked (`Pii`).

Usage and access lists each catalog entry: a limit as "{used} of {limit} {label}" or "{used} {label} · No limit", with Near limit or At limit, a feature as On or Off, and a Plan or Grant badge. Without the plans each row shows its registry key.

State history's search sends a whole state or cause label ("Payment failed", any case) as its stored code (`past_due`), since express matches stored codes; any other term goes as typed. Provider events read "Not yet" in Handled while pending and "Gave up" once failed; only a failed event's error is red, and an unused event's reason is muted.

The Invoices card reads the provider forward only, newest subscription first, 20 invoices a page at most. It has a Status filter, kept in the card for simplicity, and no search or sort, which the provider does not offer. Its query does not refetch on window focus, since each loaded page is a provider read. A page can come back short or empty while more remain, so "Load more invoices" stays while the provider says there is more, and "No invoices for this tenant." shows only once it says there is none. A refused cursor (the subscriptions changed, or payments were turned off) offers "Start again from the newest", which also reads the billing again, so payments turned off show as the payments-off note. A failure shows the API's sentence with Try again; a failed Load more keeps the invoices already read. Invoices carry no link: the provider's page shows the payer's contact details.
